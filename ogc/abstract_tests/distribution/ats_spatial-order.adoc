[[ats_distribution_spatial-order]]
[abstract_test]
====
[%metadata]
identifier:: /conf/distribution/spatial-order
target:: /req/distribution/spatial-order
test-purpose:: Verify that the rows are spatially ordered, measured by the pruning the row-group statistics allow.
test-method::
+
--
1. Read the bounding box from the geospatial statistics of each row group of the primary geometry column.

2. Compute the share of the file that a reader can skip for a query window, that is, the share held by the row groups whose bounding box does not intersect the window, as an expectation over query windows placed where the data are. The executable test suite fixes the size and the distribution of the windows and whether row groups are weighted by rows or by bytes; the expectation may be computed in closed form or estimated from sampled windows.

3. Compute the same share for a reference tiling of the extent into the same number of equal, non-overlapping row groups; verify that the file achieves the fraction of that reference skip rate fixed by the executable test suite.

4. If the file has too few row groups for the row-group bounding boxes to show an ordering (the executable test suite fixes the minimum), the test gives no verdict.

NOTE: The achievable skip rate depends on the number of row groups (two row groups can never skip more than about half), so the verdict is relative to the reference tiling rather than an absolute threshold. The metric and its threshold are maintained in the test suite rather than in this Standard, because the community is still refining them.

NOTE: Implemented by `gpio check spatial` (geoparquet-io 1.8.0, November 2026) and by Portolan's validator, following the Portolan spatial-order method: a closed form over the file footer, row groups weighted by compressed bytes, a pass at 0.65 of the reference skip rate, and no verdict below eight row groups with statistics. `geoparquet-validator` 0.3.1 implements an earlier sampled variant of the same measure.
--
